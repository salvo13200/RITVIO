# Data and external services

The current source adds voluntary Help & feedback controls. The report preview contains app version, platform and report category. Optional playback diagnostics use an explicit allowlist of bounded numeric counters, flags and known timing categories; arbitrary provider messages, titles, URLs, process IDs, account details and personal paths are omitted. Reading timings is local and copying writes only to the device clipboard. Opening the GitHub issue form sends version/platform context in that URL; timings are not put in the URL or attached automatically. GitHub sign-in, completion and submission happen there under GitHub's policy. A form opening is not a submitted report. The help flow adds no telemetry endpoint, background feedback request or cloud profile.

RITVIO uses a local profile, not a hosted RITVIO account. The app stores playlists, likes, followed artists/albums, listening history, preferences, caches and playback state on the device. It does not currently include a RITVIO analytics or advertising SDK, cloud library sync, or a hosted telemetry backend.

Windows stores its profile under `%APPDATA%\RITVIO`; development runs use the workspace's ignored `data/` directory. Android stores application data in its app sandbox. Uninstalling Android can delete this data: export important playlists first. Existing installations should be updated without uninstalling.

Internet requests are necessary for catalogue search, stream resolution, playback, artwork and lyrics. YouTube/YouTube Music, Google media/artwork hosts, LRCLIB, and optionally Apple's iTunes metadata/artwork services receive request data and the network address used to connect. Search terms, track/artist identifiers and metadata needed for each request may be sent. Provider policies apply; local storage does not make network requests anonymous. RITVIO is not affiliated with these services. Sources are also described inside Settings.

Android saving a share card writes a PNG through MediaStore into Pictures/RITVIO on supported versions. Sharing opens Android's chooser; the selected receiving application controls what happens next. Desktop image export writes to the chosen destination. Exported images and playlists may disclose the tracks or lyrics selected by the user. No cover artwork, lyrics or audio is included in the public source archive as a bundled catalogue.

The current source prepares song links for the RITVIO download page. They carry only a public track identifier and bounded title/artist text in the URL fragment (after `#`). Fragments are not included in the HTTP request to the static host; anyone receiving the complete link can read them. No lyrics, cover upload, library/profile identifier or signed stream address is added. Android image sharing attaches a short track message and link; the receiving app may keep, omit or process the caption. Saving to Gallery saves only the PNG. Desktop offers a separate copy-text-and-link action. The reference page makes no automatic catalogue/artwork request and never redirects to a supplied destination. Title/artist are sender-supplied, not authenticated metadata. Deployment must be verified before a release containing these links ships.

Logs can contain catalogue metadata, URLs and local paths. Review and redact them before posting issues. Unofficial providers may set their own logs and limits; RITVIO cannot control their retention. This document describes the code shipped here, not a claim about every downstream build.

Playback can preload a short fragment of the next track and temporarily retain received audio in bounded RAM buffers. A preloaded track may subsequently be skipped. The Windows proxy buffer is scoped to expiring stream URLs and disappears when the app closes; it does not create audio files, offline downloads or a persistent music cache. Local playback diagnostics contain aggregate counters and recent timing records, and are not uploaded automatically.

Optional donation links appear only on GitHub and in its README, not inside the applications. Clicking them takes you to PayPal or Buy Me a Coffee, which process the payment and related personal information under their own policies. No payment information is collected by RITVIO code.

The update checker in the current source contacts GitHub's public API for the official `salvo13200/RITVIO` release list. A manual check sends ordinary connection information, a generic RITVIO user agent and an optional cache entity tag; it does not send a RITVIO account, device identifier, installed version, listening history or library contents. Startup checks are off by default and, when enabled, run at most once a day. Update preferences, last-attempt/check times, notification dismissal and bounded release metadata are stored on the device. No GitHub login or access token is required. Download and release-note actions open GitHub in the user's browser, subject to that service's policies; the app does not automatically download or install a package. This checker is not present in the previously published Android 1.3.1 / Windows 0.7.5 binaries.

The public download page is hosted on GitHub Pages. It bundles its own font, screenshots and download snapshot and does not read the app's profile. It uses GoatCounter for aggregate website statistics on the official public hostname; local previews do not load the counter. No numeric visitor widget is shown to visitors. The counter is separate from GitHub repository traffic and app download counts.

Loading the public page requests GoatCounter's script from gc.zgo.at and sends page-view information to the project's goatcounter.com counter. Those services receive normal network connection information, including the requesting IP address, and the page information processed by the counter. The integration supplies a fixed page path/title and only the origin of a referring site: shared-song fragments and URL query parameters are not supplied as analytics fields. Aggregate counts are reviewed by the maintainer; they are not a count of app installations, identified people or active listeners. Blocking the counter can prevent a visit from being recorded. See [GoatCounter's privacy information](https://www.goatcounter.com/help/privacy) for its data handling. This web counter is not included in the music apps and does not receive their library, lyrics, playback history or diagnostic reports.

Platform suggestions use the browser's user agent locally; no event is uploaded specifically for that recommendation. An explicit “Check latest releases” action contacts GitHub's public API without account credentials or library data. Download, source and community links contact their respective providers when followed. GitHub keeps technical hosting/access logs under its own policy. The absence of advertising does not make these hosting, download or counter requests anonymous.
